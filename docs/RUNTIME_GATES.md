No physical Kaggle validation is implied by host tests. Use a fresh eligible free notebook session and keep checkpoints private. Do not reconnect repeatedly after a provider service limit, buy compute, change accounts to bypass a quota, or weaken these gates.

1. Verify the exact checkpoint674 outer package hash, archive CRCs, three native members and all214 finite leaves. Keep the original package read-only. The full native configuration, optimizer, RNG, environment and lifetime counters must be preserved.
2. Verify the source-distribution payload hash and exact member manifest. Import only the operator's inert definitions. Run its host inventory before importing JAX; require the pinned versions and one selected physical T4 UUID with matching PCI identity, driver and per-board telemetry. Two cards do not form one32GB device.
3. Set a finite preparation expiry, authorization expiry, one-to-eight maximum three-hour segments and bounded export wait in a copy of the template. The absolute preparation cap is October19,2026 at15:49:14UTC. Review flags default false. Changing immutable coordination after preparation is rejected.
4. Prepare once using the pinned674 package in a brand-new writable output directory. Actual allocator/pool/board evidence and the conservative compiled-memory admission must pass. No real initializer, teacher restart, saved-configuration reduction or optimizer reset is allowed.
5. At the initial export barrier, the kernel must return idle. Download the package and status. Audit with the matching host utility and exact coordination object, upload the package externally, independently download it back, and audit those actual downloaded bytes again. Only then submit the matching verified ACK.
6. Run exactly one full-configuration update675. Require24/24 planned optimizer slots, finite/legal state and valid memory admission. Audit/export/readback/ACK the new checkpoint before proceeding.
7. Verify an actual supplemental15 export and its external roundtrip/ACK. Only then is frequent durability physically validated. Every later export repeats the same external gate; local notebook disk alone is not durable.
8. At each healthy three-hour final, verify a final external ACK before explicitly arming the next segment. Existing user authorization can cover a finite bounded continuation; no new user prompt is inherent in the API. Authorization expiry, unhealthy/error terminal state or maximum segment count forbids continuation.

Auditing a downloaded export:

```bash
python runtime/kaggle_v1/audit_export_package.py \
  --package downloaded_export_package.zip \
  --status downloaded_status.json \
  --coordination coordination.local.json \
  --baseline-package retained_update674_package.zip \
  --report local/new_content_report.json
```

The coordination file contains the inner coordination object. The report path must be new and its parent must exist. For C3 use the corresponding `runtime/colab_c3/` auditor. Content-only audit success cannot fabricate an external receipt, attest hardware, authorize continuation, prove CUDA12 numerical equivalence, or establish playing strength.

If VM/Python state is lost, stop. These operators accept only the pinned674 recovery package; they do not automatically restore later exports into a new VM. Keep the newest verified external checkpoint for a separately reviewed recovery. Preserve unsaved accepted state when a save fails and report the exact error; do not blindly rerun preparation or training.
